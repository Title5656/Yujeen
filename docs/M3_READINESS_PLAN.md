# แผนเตรียมความพร้อมก่อน M3

วันที่: 8 พฤศจิกายน 2026 · ขอบเขต: แก้ฐาน M2 ที่เจ้าของอนุญาตแล้ว; **ยังไม่เริ่ม M3**

ผลตรวจรับรอบแก้ฐาน: ผ่าน350 unit tests, 34 tests บน Workers/D1 จำลอง และ16 browser tests รวมการอ่าน template เป็นตารางบนคอมพิวเตอร์/มือถือ พร้อมตรวจโค้ด ชนิดข้อมูล และ build ผ่าน รายละเอียดใน [รายงานผลล่าสุด](M2_READINESS_REPORT.md) พร้อมเริ่มพัฒนา M3 ตามขอบเขตด้านล่าง โดยยังไม่เปิดใช้งานพอร์ตจริงผ่านเว็บ

เป้าหมายคือเลือกเอกสาร Dime ชนิดที่ตรวจแล้ว เห็นชื่อหุ้น ซื้อหรือขาย จำนวน ราคาต่อหน่วย และค่าธรรมเนียมเป็นช่องข้อมูลที่ตรวจได้ โดยไม่ต้องพิมพ์ธุรกรรมใหม่ทุกครั้ง จากนั้นยืนยันเข้า Ledger และคำนวณได้เท่าที่หลักฐานรองรับ

AGENTS.md และ CODEX_START.md เป็นคำสั่งเริ่ม M0 ครั้งแรก รอบ M1/M2 และการแก้ฐานก่อน M3 เกิดจากคำสั่งเจ้าของภายหลัง ไม่แก้ประวัติ bootstrap ให้ดูเหมือนอนุญาตทุก milestone ตั้งแต่ต้น แผนนี้ไม่ใช่การอนุญาตให้ทำ M3–M6 ต่อเอง

## สิ่งที่เรียนรู้จากเอกสาร

ตรวจตัวอย่างสองหน้าในเครื่องแล้ว แบบฟอร์มมีหัวข้อ Confirmation Note / Receipt / Tax Invoice มีวันที่ Effective, Issue และ Settlement รวมทั้งคอลัมน์ Order ID, Securities [Exchange], Unit, Unit Price, Currency, Gross Amount, Fee Include Vat, Withholding Tax และ Total Amount พร้อมยอด USD และยอดเทียบ THB

ตัวอย่างนี้ไม่มีเวลา execution หรือลำดับการจับคู่ราย fill จึงควรบันทึกเป็น **รายการคำสั่งที่ยืนยันด้วยวันที่ในเอกสาร (DOCUMENT_DATE)** ใน Ledger เดียวกับข้อมูล fill เดิม ไม่เติมเที่ยงคืน ไม่ขอให้ผู้ใช้แต่งเวลา และไม่ใช้ลำดับอัปโหลดแทนลำดับซื้อขาย ยอด gross/net ที่เอกสารรายงานมีความสำคัญกว่าผลคูณของราคาต่อหน่วยที่อาจปัดเพื่อแสดงผลแล้ว

ใช้ Order ID ตรวจซ้ำภายในบัญชีอย่างระมัดระวัง ยังไม่ถือว่าเลขไม่ซ้ำทั่วโลก เลขเดิมที่กลับมาพร้อมวัน หลักทรัพย์ หรือยอดเงินต่างกันต้องตรวจ ไม่เพิ่มเป็น order ใหม่เอง และยังไม่รับเอกสารระดับ order กับ fill ปนกันสำหรับบัญชี/หลักทรัพย์เดียวกันจนมีขั้นตอนเทียบหลักฐาน เพื่อไม่ให้นับหุ้นซ้ำ ทั้ง API use case และ D1 ป้องกันเงื่อนไขนี้

ยอด THB, settlement date และ exchange ที่อ่านได้ใช้เทียบใน local Review เท่านั้น รอบนี้ไม่เก็บใน Trade/D1 จึงไม่อ้างว่าย้อนเปิดหลักฐานเหล่านี้ได้หลังล้างหน้า

รายละเอียดที่เก็บได้โดยไม่มีข้อมูลส่วนตัวอยู่ใน [M2_DIME_EVIDENCE.md](M2_DIME_EVIDENCE.md) และนโยบายคำนวณอยู่ใน [ADR 0006](adr/0006-document-date-orders.md) เอกสารหนึ่งตัวอย่างไม่ยืนยันทุก layout, intraday/rounding ของ Dime หรือการอ่านภาพด้วย OCR

## สิ่งที่เจ้าของจะใช้งานได้หลังแก้ฐาน

1. เปิด `/import` ในเครื่อง เลือก PDF และใส่รหัสผ่านในฟอร์มเมื่อจำเป็น รหัสผ่านล้างหลังการอ่านและไม่เก็บใน browser storage
2. ดูรายการที่แยกเป็นช่อง ตรวจวันที่ หลักทรัพย์ จำนวน ราคา และยอดเงินเทียบต้นฉบับ ฟิลด์ที่ไม่มีหลักฐานต้องมีคำเตือน
3. หากเป็น template อื่น ภาพสแกน หรือข้อมูลไม่ครบ หน้าเว็บบอกเหตุผลให้ตรวจ ไม่สร้างตัวเลขขึ้นเอง
4. ปุ่มบันทึกข้อมูลจริงยังปิดจนระบบสิทธิ์พร้อม รอบนี้พิสูจน์การยืนยันผ่าน internal use case และ D1 ในเครื่องเท่านั้น

การแก้ฟิลด์ที่อ่านไม่ออกอย่างเป็นระบบและ OCR ภาพจริงยังเป็นงานที่ต้องทำเพิ่มตามหลักฐานและขอบเขตที่อนุญาต ไม่อ้างว่าใช้ได้กับสลิป Dime ทุกชนิด

## ลำดับงานหลังจากนี้

| ช่วงงาน             | เป้าหมาย                                                            | เกณฑ์ตรวจรับก่อนถือว่าเสร็จ                                                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ปิดฐาน M2 ก่อน M3   | อ่าน template จริงเป็นข้อมูล ตรวจซ้ำและยืนยันภายในได้อย่างซื่อสัตย์ | synthetic layout tests, literal money/cost tests, duplicate/reload tests, historical order tests และ `lint`, `format:check`, `typecheck`, `test`, `build`, browser smoke ผ่านจริง; ระบุช่องว่างที่เหลือ  |
| M3 เมื่อเจ้าของสั่ง | Provider หุ้น US ที่ใช้งานได้จริง, FX, D1 cache และ Settings        | เปลี่ยนเฉพาะ Provider ที่มี adapter; Test Connection/Activate; quotes/FX มี source/time/quality; stale/rate-limit/error ชัด; credentials เข้ารหัสด้วย Master Key ใน Worker Secret; ไม่มี key ใน frontend |
| M4 เมื่อเจ้าของสั่ง | Holdings, Dashboard, Transactions, Watchlist และกราฟ                | จำนวน/ต้นทุนตรง Ledger; P&L unavailable มีเหตุผล; กราฟใช้ snapshots/ประวัติจริง; ใช้มือถือได้; ไม่แสดง MOCK เป็นผลลงทุนจริง                                                                              |
| M5 เมื่อเจ้าของสั่ง | ความปลอดภัย การสำรองข้อมูล Cron และใช้งานบนเว็บ                     | ผู้ไม่มีสิทธิ์เข้าถึงไม่ได้, backup/restore ผ่าน, secrets ไม่รั่ว, ตรวจ quota/license/ค่าใช้จ่ายก่อน deploy ภายใต้แผนฟรี                                                                                 |

**Authentication/Authorization เป็นเงื่อนไขก่อนเปิด private HTTP endpoints ทุกช่วงงาน** แม้อยู่ในหัวข้อ M5 ของแผนเดิม หาก M3 Settings หรือ M4 ต้องใช้ transport ข้อมูลส่วนตัว ต้องนำงานสิทธิ์ที่จำเป็นมาทำและทดสอบก่อนเปิด endpoint นั้น ไม่รอ deploy แล้วค่อยป้องกัน

รอบนี้ยังไม่เชื่อม Provider ภายนอก ไม่เก็บ API key ไม่สร้าง Dashboard/กราฟ และไม่ deploy เป้าหมายค่าใช้จ่ายประจำ **0 บาท** คงเดิม ใช้ Cloudflare D1 ฐานเดียว ไม่เพิ่มบริการ OCR หรือระบบฐานข้อมูลอีกตัว

## การวัดประสิทธิภาพก่อนเปิดใช้งานจริง

เริ่มจาก `pnpm benchmark:import` กับประวัติจำลองขนาดที่เหมาะกับผู้ใช้คนเดียว วัด parse/preview/dedup/replay แยกกัน แล้ววัดเส้นทางที่จะรันจริงใน Workers/D1 พร้อมจำนวน rows read/written และ CPU ตามแผนฟรีที่ตรวจใหม่ ผล Node local เป็น baseline เท่านั้น

ถ้าพบเกินงบ ให้ระบุว่าขั้นตอนไหนเป็นสาเหตุและค่อยเลือกวิธีลดงานพร้อม test ว่าผล Ledger เหมือนเดิม การจำกัดจำนวนรายการต่อไฟล์ไม่พิสูจน์ว่าการ replay ประวัติทั้งหมดอยู่ในงบ และไม่ใช้การเปิด paid plan เป็นทางแก้อัตโนมัติ

## วิธีรันและตรวจในเครื่อง

```sh
pnpm install
pnpm db:migrate:local
pnpm dev
```

เปิด `http://127.0.0.1:5173/import` ใช้ไฟล์ส่วนตัวเฉพาะในเครื่อง ไม่ใส่เอกสาร รหัสผ่าน หรือค่าจริงลง fixtures, logs, screenshots หรือ CI

```sh
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:smoke
pnpm benchmark:import
```

คำสั่งข้างต้นเป็นวิธีตรวจ ผลรันจริงและอุปสรรคสภาพแวดล้อมต้องอ่านจากรายงานรอบส่งมอบ ไม่ถือว่าการมีคำสั่งในแผนเท่ากับทดสอบผ่านแล้ว
